# Light Sync

A local-first smart lighting system for one room, running on a **Raspberry Pi 5** with **Home Assistant**. Three Govee
lights (a 10-segment RGBIC strip behind the TV and two bulbs) follow music, the TV picture, a PC game or the time of
day; a phone web app and a Telegram bot control it; the room camera (as numbers only) knows when someone is in the
room. Everything runs at home: no cloud service is needed for the lights to work.

## Why I built it

I wanted my room's lights to react to what I'm doing (music, a film, a game, going to sleep) without me touching
anything, while staying private (no cloud, cameras only as numbers) and saving energy (nothing left on when I'm out).
It grew into a project for learning real-time signal processing, computer vision, home automation and running a
service on a small Linux computer.

## Features

**Light modes**
- **Party**: beat detection on live audio (laptop sound or a USB conference-camera mic), BPM tracking, song changes
  and mood (calm / groove / upbeat / peak) choose strip scenes; the bulbs follow the strip.
- **TV**: a camera pointed at the TV reads the screen (perspective-mapped corners, 45 sample points) and colours each
  strip segment from the part of the picture next to it; the film's loudness drives brightness; a black screen or
  mute turns the room dark.
- **TV + Music**, **Gaming** (the game's colours come from the PC's screen over the network), **Normal** (white light
  that follows the owner's wake-up time and bedtime, and learns brightness / warmth preferences per hour),
  **Good night**, **All off**.

**Automation**
- **Presence**: a person is detected from the room camera with a pose model (MoveNet), even sitting still; lights go
  off when the room is empty and the owner's phone has left the Wi-Fi.
- **Approvals**: anything the system would turn **on** by itself asks first on Telegram (Yes / No); anything it turns
  **off** is reported with an Undo button.
- **Self-tuning**: it records when the owner undoes its automatic actions and proposes small setting changes each
  night.
- **Health checks**: internet down, a light not answering, the strip stuck off; a Wi-Fi device watcher alerts on new
  devices.
- **Prayer times**: calculated locally (ISNA, standard Asr) and used for Fajr / Maghrib lighting; an experimental
  rak'a counter uses the room camera (see Status).

**Interfaces**
- A mobile web app inside Home Assistant (Room, Sleep, Prayer, More: modes, per-mode settings, a live "now playing"
  card, camera views, logs, a screen-corner editor).
- A Telegram bot with 23 commands (`/status`, `/check`, `/net`, `/wifi`, modes, `/wake`, `/recap`, ...), answered by the
  Pi.
- A full-screen music visualizer page for the TV.

## Tech stack

| Part | Tech |
|---|---|
| Core service | Python 3 (numpy, Pillow / OpenCV on the laptop, requests), ~16,000 lines in 80 files |
| Home automation | Home Assistant (REST + WebSocket APIs, automations / scripts generated by Python setup tools) |
| Deployment | Two Home Assistant add-ons (Docker): Light Sync (Alpine) and a pose helper (Debian + ONNX Runtime) |
| Lights | Govee LAN UDP protocol, including the strip's per-segment streaming mode |
| Vision | motionEye camera streams (MJPEG), screen mapping with numpy, MoveNet pose estimation (ONNX) |
| Audio | Live microphone / system-audio capture, onset and tempo detection with numpy FFTs |
| Front end | One-file web app (HTML / CSS / vanilla JS), canvas visualizations |
| Messaging | Telegram bot through Home Assistant's Telegram integration |
| Remote access | Tailscale (only way in from outside; nothing is port-forwarded) |
| Windows helper | Python game helper (screen colours, Gaming on / off), Windows batch / PowerShell launchers |

## How it works

```
 USB cameras ──motionEye──> TV camera  ─┐                         ┌─> Govee strip (10 segments, UDP)
                            room camera ─┼─> Light Sync (Pi add-on) ─┼─> 2 Govee bulbs (UDP)
 Mic / laptop audio ───────────────────┤   main loop                └─> Home Assistant (states, scripts)
 PC game colours (game helper, HTTP) ───┘        │                          │
                                                  ├─ pose helper add-on (MoveNet, 127.0.0.1)
                                                  └─ web app + show page    └─> Telegram bot / phone
```

- `light_sync/light_sync.py`: the main loop (mode logic, smoothing, transitions).
- `light_sync/parts/`: 34 modules: audio (`ears`), camera and screen mapping (`eyes`, `screen_map`), lights
  (`bulbs`, `colours`), presence (`guard`, `pose_link`, `wifi`), automation (`auto_party`, `approve`, `learner`,
  `health`), prayer (`prayer`, `prayer_track`), web server (`web`), Telegram (`telegram_ask`).
- `pi_addon/`: the two Home Assistant add-ons (Dockerfiles, the app's server, the self-updater).
- `tools/ha_setup/`: 18 scripts that create the Home Assistant helpers, automations, scripts, dashboard and Telegram
  bot through its APIs; `tools/tests/`: a self-test and measurement scripts; `tools/pi/`: deploy to the Pi.

## Run it

You need Home Assistant (e.g. on a Raspberry Pi), Govee lights with LAN control on, and optionally motionEye cameras.

```bash
git clone https://github.com/<your-username>/light-sync.git
cd light-sync
cp secrets.example.yaml secrets.yaml     # Home Assistant token, camera password
cp .env.example .env                     # your addresses and light entities (start_lights.bat sets the same names)
pip install numpy requests opencv-python soundcard
python light_sync/light_sync.py          # on a laptop / PC
```

On the Pi: copy `pi_addon/light_sync` (and `pi_addon/light_sync_pose`) into Home Assistant's local add-ons folder,
install them from the Add-on Store, and set their options (lights, cameras). `tools/pi/send_to_pi.py` /
`tools/pi/update_pi.py` automate the copy and later updates. The Home Assistant side is created with
`python tools/ha_setup/<script>.py`.

## Status

**Working**
- All modes on the Pi (Normal, Party, TV, TV + Music, Gaming, Good night, All off), the web app and the show page.
- Presence with the pose model, home / away from the phone's Wi-Fi, approvals with Yes / No and Undo on Telegram.
- The Telegram bot, health checks, Wi-Fi device alerts, prayer times and the Fajr / Maghrib lighting.
- Self-updating add-on (the Pi pulls new files from the development laptop).

**In progress / experimental**
- **Rak'a counter**: tested on simulated data and one real session; not yet reliable from the current camera angle.
- **Self-tuning**: running, with only a few days of data.
- **Voice assistant** (Home Assistant Assist with a local LLM through the laptop): works, but the wake word is unreliable.
- Home Assistant setup is scripted for my devices; entity names and addresses need editing for another home.
- No automated unit-test suite (a self-test script checks a live installation).

## Privacy

Cameras are processed as numbers in memory (colour samples, grey grids, 17 body points); no picture is saved or sent.
The owner's own live view is opt-in. Secrets live in `secrets.yaml` (git-ignored); addresses in this repository are
examples.
